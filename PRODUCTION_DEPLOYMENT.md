```text
  one small cloudflared connector, short-lived migration/backup/ops cron jobs.
  web/worker/jobs → private loynara-postgres. No public database port.
  backup job → age encryption → PRIVATE R2 EU-jurisdiction Standard bucket.
```

**Tunnel retained, with a concrete reason:** direct Cloudflare CNAME → Railway HTTPS is technically supported and avoids a connector, but Railway's [HTTP edge logs capture request paths](https://docs.railway.com/cli/logs). Loynara currently has private card bearer paths; putting them through Railway's public edge would disclose those paths to provider logs. Cloudflare Tunnel lets Railway web stay private and avoids that Railway edge surface without changing application architecture. This adds a small metered connector service. It does **not** prove Cloudflare has no URI telemetry; inspect actual Cloudflare/tunnel logs with synthetic tokens before accepting Gate 1. Do not enable request-path debug/Logpush fields. If a later verified redaction solution makes direct Railway ingress equally safe, that can be a separate reviewed simplification.

After approval create one new named production Tunnel, `loynara-production`, **not** a Quick Tunnel. Publish `app.getloynara.com` as a Cloudflare proxied CNAME to the newly issued `<production-tunnel-UUID>.cfargotunnel.com` (the UUID does not exist yet). Keep the Mac `preview`, `mail-events` and `unsubscribe` routes working until production route tests pass; then move the existing `mail-events` and `unsubscribe` DNS/tunnel routes to that same production tunnel with exact method/path restrictions and no Access login for provider/customer flows. No nameserver or root-domain change. Browser auth uses `https://app.getloynara.com`; callback/asset routes required by Wallet providers remain disabled pending Gate 2. Verify Host/scheme forwarding, 404s on unrelated callback-host paths and authorized/denied sessions. No extra Railway public domain or TCP proxy is to be generated.

## Database, release, backup and monitoring

1. Start with a **new empty** private PostgreSQL volume in EU West; no seed/demo/preview records. Deploy a clean Node 26 build without `.env`, `var/`, `.next` caches or secrets. Inject runtime secrets only after build. `PRODUCTION_ENVIRONMENT=loynara-production`, exact HTTPS `PRODUCTION_APPROVED_ORIGIN`, `BETTER_AUTH_URL` and `PUBLIC_BASE_URL`, new auth secret, `PG_POOL_MAX=5`, no Mailpit, billing fixture, NFC development key or public registration. Keep promotional external mail independently OFF. Configure Mailgun EU only under its separate sender approval; no message is sent by infrastructure setup.
2. One-shot `NODE_ENV=production PRODUCTION_MIGRATION_APPROVED=true npm run production:migrate` uses an exact-match private `MIGRATION_DATABASE_URL`, advisory lock, empty-DB auth schema, Drizzle migrations and append-only trigger verification. Never run seed. Start `npm start -- --hostname 0.0.0.0 --port "$PORT"` and `npm run worker` as separately supervised services. Deployment health path `/api/health`; inspect failed/blocked outbox with `npm run diagnose`, controlled replay only after review.
3. Enable Railway daily volume snapshots as layer A. Run daily `npm run production:backup` as a short-lived Railway cron job: `pg_dump` streams into `age` encryption before upload to private R2; no plaintext remote object. Its S3 endpoint must be `https://<account-id>.eu.r2.cloudflarestorage.com`, with scoped bucket-only credentials, `AWS_DEFAULT_REGION=auto`, and a public `BACKUP_AGE_RECIPIENT`. Keep the private age identity **off Railway** with an identified restore owner. Layer B is the portable encrypted dump; layer C is R2 EU-jurisdiction Standard storage. Use a reviewed short retention/lifecycle rule; do not hardcode a legal period. Verify backup object and successful heartbeat. Railway snapshots are incremental, billed at volume rates and only restorable within the same project/environment.
4. R2 requires the owner to **activate a billing subscription/check-out**, even though Standard storage includes 10 GB-month, 1 million Class A and 10 million Class B operations/month free; beyond that it bills $0.015/GB-month, $4.50/million Class A and $0.36/million Class B, with no R2 egress charge. **No R2 activation is approved yet.** A 1–3 GB encrypted RC backup set with modest requests would fit the included tier if measured usage stays there, yielding an **estimated $0/month R2**, not a spending guarantee. Select EU jurisdiction at bucket creation; it cannot be changed later. [R2 setup](https://developers.cloudflare.com/r2/get-started/), [pricing](https://developers.cloudflare.com/r2/pricing/), [EU jurisdiction](https://developers.cloudflare.com/r2/reference/data-location/), [lifecycle](https://developers.cloudflare.com/r2/buckets/object-lifecycles/).
5. Restore drill: fetch an R2 object, decrypt only on a restricted isolated restore host, and run `npm run production:restore-check` against a **different fresh private PostgreSQL host/database**. Check tenant/location/membership/ledger counts against a recorded backup-time inventory, critical FKs, append-only trigger and Drizzle migration count/version. Run migration compatibility check there if needed; never write to live RC. The temporary restore service is metered and must remain within the $20 ceiling or wait for a separate spending decision. Real restore is **NOT RUN**.
6. Use Railway metrics/logs plus external UptimeRobot Free five-minute HTTPS and heartbeat monitors. Worker heartbeat, five-minute `production:ops-check` and backup success/age heartbeat must alert the operator on forced failure. Railway health check alone covers deployment readiness only. Verify actual alert delivery and certificate/domain status. No paid observability product.
