## Current runtime and choice

Next.js 16.3.6 runs as a persistent Node 26 server (`npm ci --include=dev`, `npm run build`, `npm start -- --hostname 0.0.0.0 --port "$PORT"`). The independent `npm run worker` polls the PostgreSQL outbox every five seconds, leases jobs for five minutes and can replay reviewed failed/blocked jobs. Auth and app each have a PostgreSQL pool; `PG_POOL_MAX=5` caps each at five connections. With one web and one worker replica, reserve **up to 20 application connections**, plus migration, backup and monitoring connections; confirm server `max_connections` before go-live. Web/worker need no persistent filesystem. PostgreSQL needs durable storage. Apple certificate and Google service-account files, if later enabled, require secure runtime mounts rather than Git or the client bundle. The app has `/api/health`, Mailgun webhook, restricted unsubscribe, Apple pass/update and Google asset routes. No active provider is inferred from the existence of a route.

## Production variables and refusal rules

Use provider secret variables/mounts, never `.env`, `.env.local`, `var/`, demo access files or device-test keys from this repository. Production boot now requires `PRODUCTION_ENVIRONMENT=loynara-production`, an explicit `PRODUCTION_APPROVED_ORIGIN`, exact matching HTTPS `BETTER_AUTH_URL` and `PUBLIC_BASE_URL`, remote PostgreSQL, a fresh 32+ character `BETTER_AUTH_SECRET`, `PG_POOL_MAX` from 1–10, and `SMTP_HOST=disabled`. It rejects preview origins/seeds, demo settings, local SMTP/Mailpit, billing fixture/secret, live billing before its gate, public registration and placeholder provider credentials. The production guard also rejects any local demo/preview/device-test credential file or NFC development key store in the application directory. Only the migration job gets `PRODUCTION_MIGRATION_APPROVED=true` and `MIGRATION_DATABASE_URL`; never retain that approval on web/worker.

## Release and recovery procedure after approval

1. Provision a **new empty** PostgreSQL service/volume in EU West. Require private networking; no public TCP proxy. Create separate app/migrator/backup roles with least practical privilege and verify `max_connections` headroom for at least 23 connections. Provision web, worker, production tunnel connector, one scheduled backup job, private bucket and monitor account only under the approved cost cap. Keep source branch pinned to a reviewed commit; disable unconditional Git autodeploy for the first production release.
2. Build web and worker from a **clean Git checkout** with Node 26 and `npm ci --include=dev`; exclude `.env*`, `var/` and local `.next/` caches. Build web with `npm run build` and inject runtime secrets only after build. A secret-free local checkout compiled successfully; Better Auth emitted expected missing-runtime-secret warnings during page-data collection, while startup guard still refuses to serve without real runtime secrets. A dedicated one-shot migration service uses `NODE_ENV=production PRODUCTION_MIGRATION_APPROVED=true npm run production:migrate`. It refuses a mismatched DB target, holds a PostgreSQL advisory lock, applies `drizzle/auth.sql` only on an empty DB, runs Drizzle migrations and verifies auth/app tables plus the append-only ledger trigger. **Do not run `npm run db:seed`.** Never run multiple migration jobs concurrently.
3. Start web with `npm start -- --hostname 0.0.0.0 --port "$PORT"` (Railway private service) and worker with `npm run worker` as separate supervised services. Set Railway deployment health check `/api/health`, restart policy On Failure and external continuous HTTPS monitoring; Railway's health check is only a deployment gate, not continuous uptime monitoring. Verify a web restart leaves queued work for the independently running worker; inspect `npm run diagnose`; replay only a reviewed job with `npm run worker -- --replay <job-uuid>`.
4. Use Railway cron (UTC) for `npm run production:backup` daily and `npm run production:ops-check` every five minutes. The backup command streams `pg_dump` into client-side `age` encryption before uploading to a private EU bucket, then HEAD-verifies the object. No plaintext dump is written. The restore command requires an **empty separate database host** and a database named `loynara_restore_*`, decrypts a selected object locally under mode 0600, restores and checks auth/tenant/membership/ledger tables plus the append-only trigger. Record restored counts and compare to the backup-time inventory; live counts may have advanced. Choose retention and deletion policy with owner/legal input before automation. Railway buckets currently have no lifecycle configuration, so an approved cleanup job remains to be configured; do not assume old objects expire automatically ([bucket limitations](https://docs.railway.com/storage-buckets)). Railway volume snapshots may supplement this, but cannot replace the independent restore drill ([backup caveats](https://docs.railway.com/volumes/backups)).
5. Set an external five-minute HTTPS health monitor and heartbeat monitors for worker, ops check and backup age; verify the actual alert recipient with a **forced failure**. UptimeRobot Free currently permits commercial monitoring and 50 monitors at five-minute intervals; account/contact approval still needed. Railway deployment events show restarts; `production:ops-check` fails and withholds its heartbeat on blocked, failed or overdue outbox jobs. Reconcile DB reachability via `/api/health`; review TLS certificate/domain expiry in the monitor and Cloudflare dashboard. No alert delivery has yet been tested.
6. Cut over exact approved Cloudflare hostnames only after the tunnel, private routing, TLS, origin Host/scheme, 404 restrictions, authorized/denied sessions and log-path review pass. Keep the Mac-backed routes until then. Repoint Mailgun's signed webhook and public unsubscribe hosts without another real message in this preparation pass. Verify recovery, QR checkout and provider routes on the release origin under their separate approvals.

**Logging boundary:** Next's request-URL logging is disabled and worker errors avoid payloads. A publicly exposed Railway domain would create edge HTTP logs containing request paths, including private `/card/<token>` paths ([Railway HTTP logs](https://docs.railway.com/cli/logs)); the recommended private-service Tunnel arrangement avoids Railway HTTP edge request logs. Do not enable Cloudflare Logpush fields containing `ClientRequestURI` or headers/cookies with credentials. Use `cloudflared` at info/warn level, never debug request dumps. Before Gate 1 PASS inspect real Cloudflare/Railway logs with synthetic bearer URLs and confirm retention/redaction; Cloudflare may still retain security telemetry under its own policies. Do not record full URL, QR payload, recovery token, Wallet auth, NFC material or DB credentials in application diagnostics.
