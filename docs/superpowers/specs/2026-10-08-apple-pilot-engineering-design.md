# Apple pilot engineering design

Implement the owner's accepted preflight corrections at production base `21bf48cb5fdc4139a4b931f282b197c8eb97ec83`. No deployment, Railway changes, provider requests, real mappings, physical Wallet tests, NFC, billing, campaign activation or badge changes.

## Asynchronous issuance
Managed Apple POST authenticates the current card bearer in its same-origin body, commits the stable projection and existing coalesced wallet.refresh outbox job, and returns HTTP 202 pending promptly. A same-origin card-bearer POST to /api/wallet/status returns scoped availability plus Apple preparation status. It never creates a pass or contacts a provider. A ready current projection yields a fresh 120-second HMAC ticket. Pending/creating/retry work yields pending; exhausted or blocked preparation yields a generic failure. Repeated issuance reuses the current projection and does not reset exhausted retries. Native nonproduction fixtures retain their existing local signing contract; native providers remain forbidden in production.

Customer archive GET checks the current credential, tenant, location eligibility and ready projection, then performs only one existing PassFast download GET. No generate/get/update/void/sync. HTTP DB work uses bounded acquisition, locks and operation cancellation; release/destroy expired clients so abandoned work cannot later commit. Provider HTTP timeout stays 45 seconds including body, response limit 5 MiB and redirects denied. Total managed download bound is 65 seconds; issuance/status DB work bound is 15 seconds. Polling is bounded and canceled on unmount; failure or long backoff leaves a retryable customer message rather than an infinite busy button. Lost provider outcomes are reconciled by the worker using the original serial, not by the customer request.

## Location eligibility
PASSFAST_TENANT_TEMPLATES now requires exact triples tenantId/locationId/templateId. Each scope and template is unique; UUIDs must be explicit, no global template fallback grants managed access. The member joins its tenant-owned programme and location; no browser-selected identity. Every issuance, status, archive access and worker managed sync resolves this database scope. Global flags and platform permission remain necessary. Disabled providers remain safe without mappings. Shared app assets remain operator-approved and untouched.

## Worker lifetime
Keep durable attempt-number ownership and five attempts/backoff. Renew leases only for the current processing attempt, never revive an expired lease. Independent bounded monitor heartbeat runs while provider work is active. A job lifetime supervisor bounds Wallet work to 270 seconds, inclusive of DB/network/startup/cleanup, while each provider sequence retains 240 seconds. Isolate managed Wallet execution in a child process if needed to make DB/network termination enforceable; do not promise cancellation with an uncancelled Promise.race. Lease loss or shutdown stops new claims and terminates active work safely; uncertain remote success remains durable creating/revocation state and is reconciled on recovery. Do not mark timeout complete. Forced parent termination must not leave an orphan child able to keep issuing requests. No simultaneous local ownership; stable provider identity and absolute-state updates handle already-in-flight unknown remote completion.
